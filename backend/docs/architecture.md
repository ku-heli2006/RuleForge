# Architecture and current semantics

The `domain` package contains transport-independent business records and canonical hashing; `dsl` parses conditions into a typed condition tree; `engine` evaluates conditions without invoking a solver; `verification` translates that same tree into Z3 constraints; `counterfactual` searches input equivalence representatives; `backtesting` replays a deterministic synthetic dataset; `api` adapts HTTP requests and responses; `persistence` uses JDBC and Flyway-managed PostgreSQL tables.

For frontend compatibility, a lower numeric `priority` wins (priority 1 is stronger than priority 2 in the supplied mock data). For each scalar action field, the first matching rule by priority then ID supplies that field. Different fields can come from different rules. Equal-priority incompatible values raise a conflict; no arbitrary tie is selected. Tags combine as a sorted set and reasons combine into a list. Defaults are eligible=true, discount=0, shipping=false, priority processing=false. Ineligibility forces the final discount to zero. Static overlap and conflict analysis are separate from runtime evaluation. Published database version rows are immutable; a duplicate endpoint creates a new draft.
